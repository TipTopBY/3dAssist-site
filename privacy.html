Privacy Policy for 3dAssist

Publisher / data controller: Pavel Avtushenko

Privacy contact: p_avtushenko@outlook.com

3dAssist helps users find 3D models, prepare print plans and operate a configured printer. This policy describes the behavior present in the reviewed Android code.

Data handled

  • A random per-install identifier and the device model are sent to the configured 3dAssist backend to issue and protect an app token. They are not hardware advertising identifiers.
  • If a user chooses an STL file or imports an available provider file for printing, the file and its basic metadata are sent to the configured backend for analysis and preparation.
  • Model description, selected quality goals, material, intended use and revision comments are sent to the configured backend to create and revise a print plan.
  • Print-attempt identifiers, printer display name, status events, selected rating and optional rating comment are sent to the configured backend and are also cached locally for history/offline use.
  • A search entered in a non-English language may be sent to Google’s translation endpoint to obtain an English catalog query. On-device ML Kit language identification/translation components are also bundled.
  • Optional source login opens a provider sign-in page in an in-app WebView. Provider cookies remain in Android WebView storage; app-managed cookie forwarding is restricted to declared same-provider HTTPS origins when a download needs the session. Top-level WebView pages, login popups and the hidden session check are restricted to explicitly allowed HTTPS provider/SSO hosts. Other page navigation is blocked. Third-party cookies remain enabled for SSO; embedded resources follow browser rules. 3dAssist installs no JavaScript bridge and does not intentionally read the password entered on the page.
  • A self-registered MyMiniFactory API key can be stored encrypted on the device and sent directly to that provider to enable catalog search. It is not sent to the 3dAssist backend by the reviewed client.
  • Printer address and access credentials are stored encrypted on the device and used for direct communication with the printer on the local network. These local settings are excluded from Android app-data backup. Depending on the printer protocol, this LAN traffic may be cleartext.
  • After Google sign-in, printer settings (model, display name, nozzle, capabilities and calibration) synchronize with the account on the 3dAssist backend. The address and access credentials are sent only as opaque AES-256-GCM ciphertext; the backend never receives the decryption key. Live printer snapshots and observation timestamps are not synchronized.
  • The account encryption key is protected locally by Android Keystore and stored for restoration through Google Block Store, together with its Google account identifier. The app enables cloud backup of this key record only after confirming that end-to-end encryption is available. Restoration depends on Google Play services and Android backup/restore settings; Google sign-in alone does not guarantee it. Without a usable key, printer settings return without the address and access credentials, which must be entered again.

Diagnostics

To fix errors, the app and the 3dAssist backend send reports to Sentry (processor: Functional Software, Inc.; data stored in the EU region, Germany).

  • What is sent. Reports about app crashes and freezes and about print, upload and catalog errors: stack trace, app version, device model, Android version and recent technical app events. A pseudonymous backend account identifier (owner_id) is attached; name, account email and advertising identifiers are not. The backend reports its own internal errors and model-preparation failures with the same pseudonymous identifier, without request bodies, headers or cookies.
  • What is not sent. Screenshots, screen layout, session replay, network requests and native reports are disabled. Before sending, the app strips IP addresses, saved printer credentials, tokens and URL parameters.
  • “Report a problem”. When the user chooses to send feedback from settings or an error screen, its text and an optional reply email go to Sentry.
  • Retention. Up to 90 days under the publisher's Sentry plan (30 days on the free plan), after which reports are deleted automatically.
  • How to opt out. Settings → “Send error reports”. The switch is on by default; once it is off, the app sends no further reports or feedback.

AI request processing

To prepare a print plan, the 3dAssist backend sends the request text to a language model through OpenRouter (processor: OpenRouter, Inc., USA), which forwards it to the AI model provider it selects. Their own policies govern how they retain requests.

  • What goes to the AI provider. The model description and purpose, selected quality goals, plan revision comment, material, printer profile and technical model geometry parameters; for part-type detection, the model title and description. Model files and images are not sent to the AI provider in the current version.
  • Request log (traces). For diagnostics and to improve plan quality, the backend stores AI requests and responses in an Arize Phoenix log on the publisher's server in Belarus; the log is not shared with third parties. A trace is linked to a pseudonymous session identifier derived from owner_id; the owner_id itself, email and tokens are not written to it.
  • Redacted mode. Production runs in redacted mode only: API keys, bearer tokens and other secrets are scrubbed from the text before it is written, and an image is stored only as its type, size and SHA-256 hash, without base64 content. An unscrubbed full mode can be enabled explicitly only in dev/stage test environments; production code forbids it.
  • Access. Only the publisher, through a closed administrative channel (SSH tunnel); there is no public access.
  • Retention. 30 days, after which traces are deleted automatically (checked hourly). The log is not included in backups.
  • Deletion. Deleting the account in the app does not remove traces immediately: they expire with the retention period, 30 days after they were written. On request to the address below, the publisher can delete traces earlier if the request can be matched to an account; the service does not store email, so this is not always possible.

Purposes and sharing

Data is used to provide authentication, model processing, print planning, printer control, history, translation, support of the user-requested source download, error fixing and improving print plan quality. The code contains no advertising or analytics SDK; the only error-reporting SDK is Sentry. Data is transmitted to the operator of the 3dAssist backend configured in the app, Sentry for error reports and feedback, OpenRouter and the AI provider it selects for print planning, Google translation services when translation is used, and a selected model-source provider when the user uses that provider. Provider and printer traffic is not routed to another source by the app.

Google Block Store, provided through Google Play services, stores and restores the account encryption key record to restore printer connections on another device. Google receives an end-to-end encrypted backup of this record when cloud backup is enabled by the app. The 3dAssist backend receives printer metadata and encrypted address/access credentials, but cannot decrypt them. Source-provider credentials and WebView sessions are outside account printer synchronization.

Security

Release builds require an HTTPS backend origin, and app-managed source-cookie forwarding requires an allowlisted HTTPS origin. Provider WebView page navigation is restricted to explicit HTTPS provider/SSO hosts; this is not a filter for every embedded resource or iframe. Sensitive settings use Android Keystore-backed encryption. Local printers may require cleartext LAN protocols; the reviewed manifest currently permits cleartext traffic globally, which is an open release risk documented in the policy audit.

Retention and deletion

The connected account can be deleted in Settings → Privacy and data. The app asks for confirmation; the backend deletes the account profile, favorites, print plans, uploaded files, history and account printer records, including their ciphertext. After server confirmation, the app deletes the account encryption key from Google Block Store and its local key copy before completing local cleanup. It then clears its account token, cached history/outbox and pending execution/upload data, and mints a new random install identifier. Local printer settings and provider WebView sessions are removed separately from printer/source settings or by clearing app storage. Signing out stops printer synchronization but keeps printers on the device and preserves the local key and its Block Store record. The same deletion can be requested without the app at https://tiptopby.github.io/3dAssist-site/delete-account.html. Service backups are kept for no more than 3 days, so a copy of deleted data can survive in a backup for up to 3 days after the account is deleted. AI request traces expire on their own schedule — see “AI request processing”.

Children, changes and contact

The reviewed code does not implement a children-specific experience. Material policy changes are published at this URL with a new effective date. Questions and privacy requests go to p_avtushenko@outlook.com.
