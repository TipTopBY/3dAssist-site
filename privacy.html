Privacy Policy for 3dAssist

Effective date: 2026-10-16 · published at https://tiptopby.github.io/3dAssist-site/privacy.html

Overview · Terms and Conditions · Delete account

Publisher / data controller: Pavel Avtushenko

Privacy contact: p_avtushenko@outlook.com

3dAssist helps users find 3D models, prepare print plans and operate a configured printer. This policy describes the behavior present in the reviewed Android code.

Data handled

  • A random per-install identifier and the device model are sent to the configured 3dAssist backend to issue and protect an app token. They are not hardware advertising identifiers.
  • If a user chooses an STL file or imports an available provider file for printing, the file and its basic metadata are sent to the configured backend for analysis and preparation.
  • Model description, selected quality goals, material, intended use and revision comments are sent to the configured backend to create and revise a print plan.
  • Print-attempt identifiers, printer display name, status events, selected rating and optional rating comment are sent to the configured backend and are also cached locally for history/offline use.
  • A search entered in a non-English language may be sent to Google’s translation endpoint to obtain an English catalog query. On-device ML Kit language identification/translation components are also bundled.
  • Optional source login opens a provider sign-in page in an in-app WebView. Provider cookies remain in Android WebView storage; app-managed cookie forwarding is restricted to declared same-provider HTTPS origins when a download needs the session. Top-level WebView pages, login popups and the hidden session check are restricted to explicitly allowed HTTPS provider/SSO hosts. Other page navigation is blocked. Third-party cookies remain enabled for SSO; embedded resources follow browser rules. 3dAssist installs no JavaScript bridge and does not intentionally read the password entered on the page.
  • A self-registered Cults3D username/API key and MyMiniFactory API key can be stored encrypted on the device and sent directly to that provider to enable catalog search. They are not sent to the 3dAssist backend by the reviewed client.
  • Printer address and printer credentials are stored encrypted on the device and are used to communicate directly with the printer on the local network. They are excluded from Android backup by the app rules. Depending on the printer protocol, this LAN traffic may be cleartext.

Diagnostics

To fix errors, the app and the 3dAssist backend send reports to Sentry (processor: Functional Software, Inc.; data stored in the EU region, Germany).

  • What is sent. Reports about app crashes and freezes and about print, upload and catalog errors: stack trace, app version, device model, Android version and recent technical app events. A pseudonymous backend account identifier (owner_id) is attached; name, account email and advertising identifiers are not. The backend reports its own internal errors and model-preparation failures with the same pseudonymous identifier, without request bodies, headers or cookies.
  • What is not sent. Screenshots, screen layout, session replay, network requests and native reports are disabled. Before sending, the app strips IP addresses, saved printer credentials, tokens and URL parameters.
  • “Report a problem”. When the user chooses to send feedback from settings or an error screen, its text and an optional reply email go to Sentry.
  • Retention. Up to 90 days under the publisher's Sentry plan (30 days on the free plan), after which reports are deleted automatically.
  • How to opt out. Settings → “Send error reports”. The switch is on by default; once it is off, the app sends no further reports or feedback.

Purposes and sharing

Data is used to provide authentication, model processing, print planning, printer control, history, translation, support of the user-requested source download and error fixing. The code contains no advertising or analytics SDK; the only error-reporting SDK is Sentry. Data is transmitted to the operator of the 3dAssist backend configured in the app, Sentry for error reports and feedback, Google translation services when translation is used, and a selected model-source provider when the user uses that provider. Provider and printer traffic is not routed to another source by the app.

Security

Release builds require an HTTPS backend origin, and app-managed source-cookie forwarding requires an allowlisted HTTPS origin. Provider WebView page navigation is restricted to explicit HTTPS provider/SSO hosts; this is not a filter for every embedded resource or iframe. Sensitive settings use Android Keystore-backed encryption. Local printers may require cleartext LAN protocols; the reviewed manifest currently permits cleartext traffic globally, which is an open release risk documented in the policy audit.

Retention and deletion

The connected account can be deleted in Settings → Privacy and data. The app asks for confirmation, the backend deletes the account profile, favorites, print plans, uploaded files and history, and only after confirmation the app clears its account token, cached history/outbox and pending execution/upload data, and mints a new random install identifier. Printer credentials and provider WebView sessions remain local and are removed separately from printer/source settings or by clearing app storage. The same deletion can be requested without the app at https://tiptopby.github.io/3dAssist-site/delete-account.html. Encrypted service backups are rotated out on a 14-day cycle, so a copy of deleted data can survive in a backup for up to 14 days after the account is deleted.

Children, changes and contact

The reviewed code does not implement a children-specific experience. Material policy changes are published at this URL with a new effective date. Questions and privacy requests go to p_avtushenko@outlook.com.
